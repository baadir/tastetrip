# Project guidance

Before taking any action in this project, read `Starthere.md`, then `PROJECT_HISTORY.md`, then the documents relevant to the task. Repeat this on a new session or after context loss.

Preserve decision history. Never silently override an accepted decision or treat an unapproved proposal as accepted. A new explicit user instruction can change an earlier decision; append a dated record referencing the superseded decision, preserve the old entry, and update the current summary and affected documents. If intent is ambiguous, clarify before changing the decision while continuing independent work.

After a durable decision, finding, external action, or state change, append a record to `PROJECT_HISTORY.md`. Distinguish user-reported state from verified state and draft content from submitted content. Do not put credentials or API keys in the history.

For product UX work in TasteTrip Concierge, read `.agents/skills/product-design-and-ux/SKILL.md` and only the references relevant to the current scope. This skill is installed locally in the project.

Treat UX recommendations as hypotheses until the user adopts them or they are validated. Do not invent user research or implemented capabilities. Keep `PRODUCT_REQUIREMENTS.md` as the product baseline and `docs/ux/01-entry-and-login.md` as the initial UX discussion record.

External skills may reference adjacent skills not installed here. Those are routing suggestions, not a requirement to install more packages or stop an otherwise authorized UX task.
